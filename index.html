How these projects are built

Most of the day-to-day work is done by an AI agent. A human owns the repositories and sets the direction. Three habits make that checkable.

1

Tested over the real interface

Every feature gets a test that drives the real thing: a real server, a real socket, a real client. Unit tests alone do not count as done.

2

Additive public API

Changes to the public API are additive. A break means a major version, a MIGRATION.md, and deprecation across at least one minor release first.

3

Released, not just merged

A feature has shipped when you can install it. Releases are tagged on a fortnightly schedule, with an exception for security fixes and broken installs.

Upstream pins

A project that wraps something else says what it was built against. Each repository has an UPSTREAM.md with the pinned reference and the date it was last checked. A passing test suite does not tell you the pin has aged.
